# 다음 세션 작업 가이드 (Sonnet 사용)

이후 작업은 Sonnet으로 진행한다. Sonnet은 유능하지만 **맥락을 스스로 복원하지 않는다.**
아래 형식을 지키면 매 세션 처음부터 설명할 필요가 없다.

---

## 모든 세션의 첫 프롬프트에 넣을 고정 머리말

```
docs/ROADMAP.md, docs/DECISIONS.md, docs/METHODOLOGY.md, config/params.yaml 을 먼저 읽어.
CLAUDE.md의 4원칙을 지켜. 특히 방법론에 의문이 생기면 코드를 쓰기 전에 나에게 물어봐.

이번 세션 작업: T-XXX
```

`T-XXX`만 바꿔가며 재사용한다. 문서가 맥락을 나르므로 매번 배경 설명을 반복하지 않아도 된다.

---

## 한 세션 = 한 Phase, 최대 3~4개 작업

작업을 몰아서 시키면 Sonnet이 검증을 건너뛰고 진도만 나간다.
**작업 하나가 끝날 때마다 완료조건을 확인시키고 넘어간다.**

| 세션 | 다루는 작업 | 비고 |
|------|------------|------|
| 1 | T-003, T-004, T-005 | 환경 구성 + 푸시. 짧게 끝난다 |
| 2 | T-201 ~ T-203, T-206 | 필지 마스터. `encoding='cp949'` 주의 |
| 3 | T-301, T-302 | 하드필터 + 사업성. **기대값 재현 확인이 핵심** |
| 4 | T-104, T-304 | 지하철역 + 역세권 등급 |
| 5 | T-204, T-303 | 일조환경. **T-102b 완료 후에만 가능.** 무겁고 까다롭다 |
| 6 | T-305, T-306 | 계층 정렬 + **사용자와 결과 검증** |
| 7 | T-401 ~ T-403 | 타일 빌드 |
| 8~10 | T-501 ~ T-507 | 웹. taste-skill 적용 |
| 11 | T-601 ~ T-604 | 배포 |

세션 2~4는 T-102b(건물데이터) 없이도 진행 가능하다. 다운로드를 기다리며 먼저 해도 된다.

T-102b(GIS건물통합정보 다운로드)는 사용자가 세션 밖에서 처리한다.

## 프롬프트 예시

### 데이터 처리 세션
```
docs/ROADMAP.md, docs/DECISIONS.md, docs/METHODOLOGY.md, config/params.yaml 을 먼저 읽어.
CLAUDE.md의 4원칙을 지켜.

이번 세션 작업: T-201 ~ T-203 (필지 마스터 구축)

데이터는 data/raw/land_characteristics/11290/ 에 있어.
속성 인코딩이 CP949야. .cpg 파일이 UTF-8로 잘못 표기돼 있으니 반드시 명시해.
스크립트는 scripts/ 에, 결과는 data/interim/ 에 써.
ROADMAP의 완료조건(52,970행, 용도지역 비율)이 재현되는지 확인하고 알려줘.
```

### 지표 구현 세션
```
(고정 머리말)

이번 세션 작업: T-303 (일조환경 지표)

METHODOLOGY.md 3장의 정의를 그대로 구현해. 임의로 바꾸지 말고,
정의에 빈틈이 있으면 구현 전에 지적해줘.
필지 5.3만 개라 성능이 중요해. STRtree 색인과 numpy 벡터화를 쓰고,
전체 실행 시간을 마지막에 보고해.
완료되면 표본 10필지를 뽑아서 점수가 타당한지 같이 보자.
```

### 웹 구현 세션
```
(고정 머리말)

이번 세션 작업: T-502 (브라우저 점수 엔진)

.claude/skills/taste-skill/SKILL.md 를 읽고 디자인 지침으로 삼아.
다만 이 스킬은 랜딩페이지용이라 대시보드는 범위 밖이야.
시각 언어만 가져오고 레이아웃은 지도 대시보드 관례를 따라.

가장 중요한 건 정확성이야. 같은 파라미터에서 Python 결과와
JS 결과의 상위 100개 순위가 일치하는지 반드시 대조해줘.
계층 정렬은 3단계고, 역세권 등급까지 같으면 S1 원값으로 최종 정렬해.
```

네 추천을 하나씩 제시해줘. 내가 고르면 DECISIONS.md 에 반영해.

## Sonnet에게 자주 해야 할 교정

이 프로젝트에서 실제로 사고가 나기 쉬운 지점들이다. 미리 못 박아두면 좋다.

| 상황 | 미리 넣을 문장 |
|------|---------------|
| 좌표계 | "거리·면적 계산은 EPSG:5186에서 해. 위경도로 거리 계산하지 마." |
| 파라미터 | "숫자를 코드에 하드코딩하지 마. `config/params.yaml`에서 읽어." |
| 웹 점수 | "점수를 미리 계산해서 타일에 굽지 마. raw 값만 넣고 브라우저에서 계산해." |
| 조인 | "조인율을 출력해. 말없이 결측 행을 버리지 마." |
| 인코딩 | "토지특성정보는 `encoding='cp949'`. .cpg가 UTF-8로 잘못 적혀 있어." |
| 기대값 | "ROADMAP의 완료조건 수치가 재현되는지 확인해. 안 맞으면 멈추고 알려줘." |
| 성능 | "5.3만 필지야. 행 단위 `for` 루프나 `.apply()` 쓰지 마." |
| 범위 | "ROADMAP의 이번 작업만 해. 다음 단계까지 미리 만들지 마." |

## 세션 종료 시 정리

Sonnet에게 마지막으로 시킬 것:

```
이번 세션 마무리하자.
1. ROADMAP.md 에서 끝낸 작업 체크박스를 갱신해.
2. 방법론이나 결정이 바뀐 게 있으면 METHODOLOGY.md / DECISIONS.md 에 반영해.
3. 다음 세션이 알아야 할 게 있으면 ROADMAP.md 맨 아래 "지금 막혀 있는 것"에 적어.
4. 변경사항을 커밋해.
```

이걸 매 세션 끝에 하면 문서가 항상 최신 상태를 유지하고, 다음 세션이 곧바로 이어받는다.
