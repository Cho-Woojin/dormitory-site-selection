# 임대형기숙사 적합 필지 탐색 지표 — 방법론

> 이 문서가 프로젝트의 사양서다. 코드는 이 문서를 구현할 뿐이고,
> 방법이 바뀌면 **코드보다 이 문서를 먼저 고친다.**

## 0. 핵심 구조: 가중합이 아니라 "오차범위 계층 정렬"

사용자가 정의한 탐색 방식은 가중 평균이 아니다. **우선순위가 있는 4단계 정렬**이며,
각 단계는 앞 단계의 오차범위(tolerance) 안에서만 작동한다.

```
1순위  사업성 (공시지가 대비 수익률)
         └─ 오차범위 tol₁ 안에서 동급 취급
2순위      일조환경
             └─ 오차범위 tol₂ 안에서 동급 취급
3순위          역세권 등급 (계단식)
                 └─ 같은 등급이면
4순위              수요 지표
```

가중합으로 뭉개면 "사업성이 압도적인 필지가 일조 때문에 밀리는" 일이 생긴다.
계층 정렬은 그것을 막는다. **tolerance 값 자체가 웹에서 조정할 주요 파라미터다.**
`tol₁ = 0` 이면 순수 사업성 순위, `tol₁`이 커질수록 일조·역세권이 순위를 지배한다.

### 구현: 백분위 밴드 방식

```
band₁ = floor( (100 − percentile(S₁)) / tol₁ )     # tol₁ = 5 이면 5%p 단위, 0이 최상위
band₂ = floor( (100 − percentile(S₂)) / tol₂ )
grade₃ = 역세권 등급 (A~E, 이미 이산값)
최종 정렬키 = (band₁ ↑, band₂ ↑, grade₃ ↑, S₄ ↓)   # 사전식 비교
```

백분위를 쓰는 이유: S₁은 수익률(0.03~0.12), S₂는 0~1 스케일이라 절대 오차범위를 공유할 수 없다.
백분위로 정규화하면 tolerance가 두 지표에서 같은 의미("상위 몇 %p 차이까지 동급으로 볼 것인가")를 갖는다.

## 1. 하드 필터 (점수 계산 이전 단계)

여기서 걸러진 필지는 순위에 들어가지 않는다. 근거는 [DECISIONS.md D-002](DECISIONS.md).
웹 UI에서는 "제외 필지 보기" 토글로 사유와 함께 확인할 수 있게 한다.

| 코드 | 조건 | 제외 사유 |
|------|------|-----------|
| `F1` | 용도지역에서 공동주택 건축 불가 | 1종전용주거·녹지·보전지역 등 |
| `F2` | 개발제한구역 / 공원 / 학교시설 등 저촉 | 건축 자체 불가 |
| `F3` | 필지면적 < `min_lot_area` | 20실을 담을 수 없음 |
| `F4` | 접도 없음 (건축법 제44조 미충족) | 맹지 |
| `F5` | 추정 실 수 < 20실 | 임대형기숙사 법정 최소 규모 미달 |
| `F6` | 국공유지 / 종교·학교 부지 등 취득 불가 지목 | 매입 대상 아님 |

`F5`가 실질적인 규모 하한이다:
```
추정 실 수 = 가용연면적 × 전용률 / 실당면적
```
전용률 0.65, 실당면적 16㎡ 가정 시 20실 = 약 492㎡ 연면적이 필요하다.
2종일반주거(250%)에서는 필지 약 197㎡(≈60평), 1종일반주거(150%)에서는 약 328㎡(≈99평)가 하한이 된다.
**즉 용도지역에 따라 최소 필지 규모가 달라진다. 단일 면적 컷을 쓰면 안 된다.**

## 2. S₁ · 사업성 지표

### 2.1 계산식

```
토지비        = 개별공시지가(원/㎡) × 필지면적(㎡) × 실거래배율
적용용적률    = 용도지역별 상한 (성북구 실제 도형에서 공간조인, D-001)
가용연면적    = 필지면적 × 적용용적률 × 실현계수
공사비        = 가용연면적 × 단위공사비(원/㎡) × (1 + 부대비율)
총사업비      = 토지비 + 공사비

연간임대수입  = 가용연면적 × 전용률 × 임대단가(원/㎡/월) × 12 × (1 − 공실률)
NOI          = 연간임대수입 × (1 − 운영비율)

S₁ = NOI / 분모
```

`분모`는 설정에서 고른다:
- `total_cost` (기본) — 총사업비 기준. 실무적 초기수익률(Cap rate)에 해당.
- `land_cost` — 토지비 기준. 사용자가 말한 "공시지가 대비 수익률"에 더 가깝다.

두 값 모두 산출해서 타일에 넣고, 웹에서 전환할 수 있게 한다. 어느 쪽이 옳은지는 Q-02에서 합의한다.

### 2.2 적용용적률 표 (서울특별시 도시계획조례)

`config/params.yaml`에 실려 있으며 **2025년 한시 완화가 기본 적용**된다 (D-005).

| 용도지역 | 기본 용적률 | 한시완화(~2028-05-18) | 건폐율 | 공동주택 |
|----------|------------|----------------------|--------|----------|
| 제1종전용주거 | 100% | — | 50% | 불가 |
| 제2종전용주거 | 120% | — | 40% | 가능 |
| 제1종일반주거 | 150% | — | 60% | 가능(층수제한) |
| 제2종일반주거 | 200% | **250%** | 60% | 가능 |
| 제3종일반주거 | 250% | **300%** | 50% | 가능 |
| 준주거 | 400% | — | 60% | 가능 |
| 근린상업 | 600% | — | 60% | 가능 |
| 일반상업 | 800% | — | 60% | 가능 |
| 준공업 | 400% | — | 60% | 가능 |
| 자연녹지 | 50% | — | 20% | 불가 |

> ⚠️ 이 표와 "공동주택 가능" 열은 **T-102에서 조례 원문과 대조 검증이 필요하다.**
> 특히 1종일반주거의 층수 제한, 상업지역 주거복합 비율 조건은 조례 확인 전까지 잠정값이다.

### 2.3 실현계수 (미결 Q-01)

용적률 상한을 100% 소진하는 건물은 현실에 드물다. 일조사선·도로사선·주차·정형성 손실 때문이다.
1단계에서는 상수 `0.85`로 두되, 2단계에서 필지 형상에서 유도하는 방식을 검토한다:
```
실현계수 = base × 정형성계수(면적 / 최소외접사각형면적) × 세장비계수
```

## 3. S₂ · 일조환경 지표

사용자 정의: *"바로 옆에 건축물이 있는지 없는지, 있다면 얼마나 높은지.
이런 상황이라면 도로를 면하는 건축물이 우선순위가 높을 수도 있다."*

### 3.1 물리적 근거

서울(위도 37.59°N)의 **동지 정오 태양고도 ≈ 28.97°** 이다.
남측 인접 건물을 올려다본 앙각이 이 값을 넘으면 동지에 정오 직사광이 차단된다.

```
앙각θ = atan( (인접건물높이 − 기준높이) / 수평거리 )
```

### 3.2 개방도(openness) 산출

필지 대표점에서 방위각 섹터별로 최대 앙각을 구하고, 열린 정도를 합산한다.

```
섹터: 남서 ~ 남동 (135°~225°) 를 15° 간격으로 분할
각 섹터 s 에 대해:
    θ_max(s) = 반경 R(기본 50m) 내 건물들의 최대 앙각
    open(s)  = clamp( (θ_ref − θ_max(s)) / θ_ref , 0, 1 )   # θ_ref = 28.97°

S₂_raw = Σ w(s) · open(s) / Σ w(s)        # w(s)는 정남에 가까울수록 큰 가중치
```

### 3.3 접도 보너스 — 사용자가 직접 지적한 항목

도로에 면한 방향은 **영구적으로 열려 있다.** 옆 필지는 언제든 건물이 올라갈 수 있지만
도로는 그렇지 않다. 따라서 남측이 도로면 일조가 구조적으로 보장된다.

```
S₂ = S₂_raw × (1 + road_bonus × 남측접도여부 × min(도로폭 / 12m, 1))
```

도로에 접하지 않은 방향의 나대지(현재 빈 땅)는 **미래에 건물이 설 것으로 가정**해
용도지역 상한 높이로 채워 계산하는 보수적 옵션(`assume_future_buildout`)을 둔다.
지금 옆이 비어 있다는 이유로 높은 점수를 받는 필지는 위험한 추천이다.

### 3.4 연산 비용 경고

필지 6~8만 개 × 반경 50m 내 건물 탐색이다. 순진하게 구현하면 몇 시간 걸린다.
`geopandas.sjoin` + STRtree 공간색인 + numpy 벡터화로 처리하고, 중간 결과를 캐시한다.
이 단계는 사전 계산이며 브라우저에서 재계산하지 않는다.

## 4. S₃ · 역세권 등급 (계단식)

사용자 정의: *"역까지의 거리를 계단식으로 값을 지정해. 등급을 나눈다."*

| 등급 | 거리 | 통상 도보시간 |
|------|------|--------------|
| A | ≤ 250m | 약 3분 |
| B | ≤ 500m | 약 7분 |
| C | ≤ 750m | 약 10분 |
| D | ≤ 1,000m | 약 13분 |
| E | > 1,000m | — |

- 1단계는 **직선거리**로 산출한다. 성북구는 구릉지·막다른 길이 많아 직선거리가 도보거리를 과소평가하지만,
  6~8만 필지 × 도보 네트워크 최단경로는 초기 단계에 과한 비용이다.
- 2단계 개선안: OSM 보행 네트워크 기반 실제 도보거리 (`osmnx`). 개선 효과가 크면 그때 도입한다.
- 임계값 4개 모두 웹 슬라이더로 조정 가능하게 한다.

### 대상 역 (성북구 및 경계 인접)

| 노선 | 역 |
|------|-----|
| 1호선 | 석계, 광운대(인접) |
| 4호선 | 한성대입구, 성신여대입구, 길음 |
| 6호선 | 보문, 안암, 고려대, 월곡, 상월곡, 돌곶이, 석계 |
| 우이신설선 | 정릉, 북한산보국문, 솔샘(인접) |
| 동북선(건설중) | 미결 Q-05 — 포함 여부 사용자 합의 필요 |

역 목록은 데이터에서 자동 추출하되, 성북구 경계에서 **버퍼 1.5km까지 확장**해 수집한다.
구 경계 바로 밖의 역이 구 안 필지의 역세권을 결정하는 경우가 많다.

## 5. S₄ · 수요 지표 (사용자가 "추천해줘"라고 남긴 자리)

### 권장: 대학 수요 중력지수

성북구는 **대학이 6개 있는 구**다. 임대형기숙사 수요의 압도적 결정 요인이며,
다른 어떤 인구지표보다 이 사업의 본질에 가깝다.

```
S₄ = Σᵢ ( 재학생수ᵢ / max(거리ᵢ, 200m)^β )        # β 기본 1.5
```

| 대학 | 위치 |
|------|------|
| 고려대학교 | 안암동 |
| 국민대학교 | 정릉동 |
| 성신여자대학교 | 동선동 |
| 한성대학교 | 삼선동 |
| 서경대학교 | 정릉동 |
| 동덕여자대학교 | 하월곡동 |
| 광운대학교 | 노원구(성북구 동측 인접) |

### 보조 후보 (합의 후 채택 — Q-06)

1. **청년 1인가구 밀도** — 행정동별 20~34세 1인가구 / 면적. KOSIS·서울 열린데이터광장.
2. **경쟁 공급 밀도** — 반경 내 기존 기숙사·고시원·다중생활시설 연면적. 건축물대장 용도코드로 산출. **음의 지표.**
3. **평균 경사도** — 성북구는 정릉·성북동 등 구릉지가 넓다. 공사비와 접근성 모두에 영향.
   DEM에서 산출하며, 임계 이상은 하드 필터로 올리는 것도 검토.

## 6. 웹에서 실시간 조정 가능한 파라미터

브라우저가 raw 값에서 점수를 다시 계산하므로 아래는 전부 **재빌드 없이** 바뀐다.

| 그룹 | 파라미터 | 기본값 |
|------|----------|--------|
| 계층 | `tol₁` 사업성 오차범위 (%p) | 5 |
| 계층 | `tol₂` 일조 오차범위 (%p) | 10 |
| 사업성 | 실거래배율 | 1.5 |
| 사업성 | 단위공사비 (만원/㎡) | 250 |
| 사업성 | 임대단가 (원/㎡/월) | 25,000 |
| 사업성 | 공실률 / 운영비율 | 0.05 / 0.25 |
| 사업성 | 실현계수 | 0.85 |
| 사업성 | 수익률 분모 | 총사업비 |
| 용적률 | 2025 한시완화 적용 | ON |
| 역세권 | 등급 임계 (m) | 250 / 500 / 750 / 1000 |
| 필터 | 최소 실 수 | 20 |
| 필터 | 제외 필지 표시 | OFF |

> 기본값은 전부 **가정**이다. 실제 성북구 시세로 검증하기 전까지 결과를 의사결정에 쓰면 안 된다.
> 웹 UI 상단에 이 경고를 표시한다.

### 타일에 담을 raw 속성 (10개 내외 — D-003 제약)

`pnu`, `area`, `zone`, `far`, `price`, `sun`, `stn_d`, `uni_g`, `slope`, `road_w`, `flags`

`flags`는 하드 필터 통과 여부를 담은 비트마스크다 (F1~F6).
