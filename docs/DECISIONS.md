# 결정 로그 (Decision Log)

프로젝트의 되돌리기 어려운 선택들을 기록한다. 새 세션은 이 문서를 먼저 읽고 시작한다.
결정을 바꿀 때는 기존 항목을 지우지 말고 `상태: 폐기 → D-0XX로 대체` 로 표시한다.

## D-001 · 가용면적 = 건축가능 연면적

**상태:** 확정 (2026-08-31)

`가용연면적 = 필지면적 × 적용용적률 × 실현계수`

- 필지 면적을 그대로 쓰지 않는다. 성북구는 1종일반주거(150%)와 3종일반주거(300%)가 섞여 있어
  같은 면적이라도 건축 가능한 연면적이 2배 차이 난다. 면적만 쓰면 사업성이 왜곡된다.
- **적용용적률은 성북구 실제 용도지역 도형을 필지에 공간조인해서 결정한다.** 구 전체 단일값 금지.
- 실현계수는 정형성·사선제한·주차 등으로 인한 미실현분을 반영하는 0~1 계수. 파라미터화한다.

**따라오는 요구:** 용도지역 데이터(`LT_C_UQ111` 또는 NSDI 국토계획구역)가 없으면 이 프로젝트는 성립하지 않는다. 데이터 확보 1순위.

## D-002 · 임대형기숙사 법규는 하드 필터로 적용

**상태:** 확정 (2026-08-31)

법적으로 임대형기숙사를 지을 수 없는 필지는 점수를 깎는 게 아니라 **후보군에서 제외**한다.

근거 법령 (검증 태스크 T-102에서 원문 대조 필요):
- 건축법 시행령 별표1 제2호(공동주택) 라목 「임대형기숙사」
  - 공공주택사업자 또는 민간임대주택법상 임대사업자가 임대사업에 사용
  - **임대 목적 실이 20실 이상**
  - 공동취사시설 이용 세대 수가 전체의 50% 이상
  - 용도상 면적 제한·층수 제한 없음
- 해당 용도지역에서 **공동주택 건축이 가능**하면 임대형기숙사도 가능

하드 필터 항목:
1. 용도지역 — 공동주택 불가 지역(1종전용주거, 녹지지역 등) 제외
2. 최소 규모 — 20실을 물리적으로 담을 수 없는 필지 제외 (D-005 참조)
3. 접도 — 건축법 제44조 접도의무 미충족 필지 제외

**트레이드오프:** 경계선상 필지가 지도에서 사라진다. 이를 보완하려고 웹 UI에서 "제외 필지 보기" 토글을 제공한다 (제외 사유를 함께 표시).

## D-003 · 웹은 MapLibre GL JS + PMTiles 정적 배포

**상태:** 확정 (2026-08-31)

GitHub Pages에는 백엔드가 없다. 그런데 사용자는 파라미터를 실시간으로 조정해야 한다.
이 둘을 동시에 만족시키는 유일한 구조:

> **점수를 미리 계산해서 굽지 않는다. 정규화된 raw 지표값을 필지 속성으로 타일에 넣고,
> 최종 점수는 브라우저에서 가중합으로 계산한다.**

- 성북구 필지는 대략 6~8만 개 → GeoJSON 전체는 수백 MB라 불가. PMTiles 벡터타일로 압축.
- PMTiles는 HTTP Range 요청만으로 동작하므로 타일 서버가 필요 없다. GitHub Pages에서 그대로 서빙된다.
- 점수 변화는 MapLibre expression 또는 `feature-state` 재바인딩으로 반영한다.
- MapLibre는 Mapbox와 달리 액세스 토큰이 필요 없다. 과금 지점이 없다.

**제약:** 타일 속성에 담는 지표 수만큼 파일이 커진다. 지표는 최종 10개 내외로 제한한다.

## D-006 · 실현계수는 필지 형상·경사에서 유도한다 (Q-01 확정)

**상태:** 확정 (2026-08-31)

토지특성정보(AL_D194)에 필지 형상(`A22`)과 경사(`A20`)가 **실측값으로 이미 들어 있다.**
고정 상수를 쓸 이유가 없다.

```
실현계수 = base(0.90) × 형상계수 × 경사계수
```

| 형상 | 계수 | | 경사 | 계수 |
|------|------|--|------|------|
| 정방형 | 1.00 | | 평지 | 1.00 |
| 가로장방 | 0.98 | | 저지 | 0.97 |
| 세로장방 | 0.95 | | 완경사 | 0.95 |
| 사다리형 | 0.92 | | 급경사 | 0.85 |
| 부정형 | 0.85 | | 고지 | 0.85 |
| 자루형 | 0.75 | | | |

`base = 0.90`(사선제한·주차 등 공통 감가)만 가정치이고 나머지는 실측 기반이다.
실측 결과 실현계수 분포는 중위 0.83, 범위 0.57~0.90.

## D-007 · 임대료 66만원 + 보증금 1,000만원, 분모는 순투자금 (Q-02·Q-03 확정)

**상태:** 확정 (2026-08-31)

초기 가정(40만원/실)으로는 중위 수익률이 **2.4%** 로, 개발사업 통상 기대치(4~7%)를 크게 밑돌았다.
역산 결과 수익률 4%에 필요한 임대료는 실당 62만원이었고, **2026년 고려대 인근 원룸 평균 월세가
66.3만원**(전년비 +9.8%)이었다. 즉 가정이 틀렸던 것이지 성북구가 사업성이 없는 게 아니다.

```
S₁ = NOI / (총사업비 − 보증금총액)
```

보증금은 무이자 조달자금이므로 실투자금을 줄인다. 비용에서 빼는 게 실무에 맞다.
다만 실측상 보증금은 총사업비의 **7%** 수준이라 수익률을 3.8% → 4.1% 로 0.3%p 올리는 정도다.

- 실당 월임대료 **660,000원** [시세]
- 실당 보증금 **10,000,000원** [시세]
- 공시지가 → 실거래가 배율 **1.5** 유지 (통상 1.4~1.7, 슬라이더 항목)

**결과:** 중위 수익률 4.1% (5~95%: 3.0~5.4%). 정상 범위.

> 이후 [D-011](#d-011--상업지역은-주거용-용적률-400-상한을-적용한다-q-10-확정) 적용으로 **4.0% (2.7~5.0%)** 로 갱신됨.

## D-011 · 상업지역은 주거용 용적률 400% 상한을 적용한다 (Q-10 확정)

**상태:** 확정 (2026-08-31)

T-302 최초 실행에서 **상위 200 필지 중 199개가 상업지역**으로 나왔다 (일반상업 144, 근린상업 55).
용도지역 용적률과 수익률의 상관이 **+0.43** 으로, 사업성이 아니라 용적률이 순위를 지배하고 있었다.

원인: 일반상업지역에 용적률 800%를 그대로 적용했으나,
**서울특별시 도시계획 조례 별표**(제31조제1항제1호·제55조제3항 관련)는
「상업지역 내 주거복합건축물의 **주거용 부분 용적률은 400% 이하**」로 제한한다.
임대형기숙사는 준주택이므로 주거용에 해당한다.

`config/params.yaml` 의 각 용도지역에 `far_residential` 필드를 두고,
적용용적률 = `min(용도지역 용적률, far_residential)` 로 클램프한다.
상업지역 4종(중심·일반·근린·유통) = 400. 나머지는 `null`(상한 없음).

### 적용 전후

| | 적용 전 (800%) | 적용 후 (400%) |
|---|---|---|
| 후보 수 | 5,238 | **4,896** |
| 중위 수익률 | 4.1% | **4.0%** (5~95%: 2.7~5.0%) |
| 상위200 일반상업 | 144 | **0** |
| 상위200 일반주거 | 0 | **131** |
| 상위200 준주거 | 1 | 55 |
| **용적률 상관** | **+0.43** | **+0.01** |
| **공시지가 상관** | −0.34 | **−0.74** |

**상관 변화가 핵심 근거다.** 적용 전에는 용적률이 순위를 만들었고,
적용 후에는 공시지가(−0.74)가 만든다. "공시지가 대비 사업성"을 재는 지표로서 후자가 옳다.

**미반영 (의도적):** 상업지역 비주거 의무비율(연면적 10% 이상, 2025년 20%→10% 완화).
반영하면 주거 연면적이 한 번 더 줄지만, 상가 부분의 임대수익을 0으로 보는 것도
부정확하므로 지금은 두지 않는다. 상업지역은 이미 상위권에서 대부분 빠졌다.

## D-012 · 높이 미상 건물은 바닥면적으로 추정한다 (Q-09 확정)

**상태:** 확정 (2026-08-31)

성북구 건물 40,368동 중 **10,009동(24.8%)** 이 높이·층수를 둘 다 갖고 있지 않다.

**"용적률·건폐율로 추론" 은 불가능했다.** 그 10,009동은 건폐율 2건, 용적률 2건,
연면적 58건(0.6%)뿐으로 해당 필드도 비어 있다. 건축물대장이 연계되지 않은 건물들이다.

대신 **폴리곤 바닥면적**을 쓴다. 이건 100% 존재하고 예측력이 있다:

```
corr(log 바닥면적, 층수) = +0.52
```

| 바닥면적 | 중위 층수 | | 바닥면적 | 중위 층수 |
|----------|-----------|--|----------|-----------|
| < 20㎡ | 1 | | 100–200㎡ | 3 |
| 20–40㎡ | 1 | | 200–500㎡ | 4 |
| 40–60㎡ | 2 | | 500㎡+ | 10 |
| 60–100㎡ | 2 | | | |

성북구 층수 유효 건물 30,349동에서 산출한 실측 표다.
`solar.unknown_building.method` 로 `exclude` 전환 가능.

**제외하지 않은 이유:** 미상 건물의 바닥면적 중위는 31㎡로 대부분 부속건물이지만,
**200㎡ 이상이 397동, 최대 9,285㎡** 있다. 이들을 없는 셈 치면 인접 필지의 일조가
낙관적으로 부풀려진다. 참고 검증(층수 아는 건물 대상):

## D-013 · 거리·정렬의 기준점 정의

**상태:** 확정 (2026-08-31)

구현 중 두 번의 검증 실패로 드러난 정의 공백을 메운다.

**1. 역까지 거리는 필지 대표점 기준이다.**
폴리곤 경계 기준으로 재면 항상 더 짧게 나와 등급과 어긋난다.
(한성대입구 250m 내 필지가 경계 기준 980개 / 대표점 기준 924개)

**2. `tol=0` 검증은 "순위 배열 일치"가 아니라 "S₁ 단조 비증가"로 한다.**
S₁ 동점 필지가 282건 있고, 계층 정렬은 이를 S₂로 타이브레이크한다.
이는 방법론상 **올바른 동작**이다 — `rank(method="first")` 는 행 순서로
임의 정렬하므로 오히려 나쁘다. 검증해야 할 불변식은 순위 순서대로 S₁이
증가하지 않는다는 것이다.

## D-014 · T-306 검증에서 드러난 세 가지 수정

**상태:** 확정 (2026-09-01)

상위 20필지를 실제로 들여다본 결과 지표가 세 군데에서 현실과 어긋났다.

**1. 하천 부지가 6위였다.** `excluded_landuse` 에 `하천등`·`운동장등` 이 빠져 있었다.
성북동 276-3(1,639㎡)은 지목이 '대'라 F6를 통과했지만 토지이용상황이 `하천등` 이다.
→ 필터에 추가. 후보에서 부적합 토지이용상황 **0건** 확인.

**2. 철거비를 넣지 않았다.** 후보의 **90%(4,407/4,894)** 에 기존 건물이 서 있는데
사업비에 철거비가 없었다. 기존 건물이 큰 필지가 부당하게 유리해진다.
```
총사업비 = 토지비 + 공사비 + 철거비
철거 연면적 = Σ(건물 바닥면적 × 추정 층수)
```
`demolition_cost_per_sqm: 100,000` 원/㎡. 중위 철거비 0.6억(총사업비의 1.3%),
중위 수익률 4.0% → **3.9%**.

**3. 다세대는 구분소유다.** 후보의 23%(1,141건), 상위 20 중 8건이 다세대주택 부지다.
다세대는 구분등기라 전 세대 동의가 필요해 매입 난이도가 아파트·연립과 같다.
그런데 아파트·연립은 하드 제외하면서 다세대는 통과시키고 있었다 — 일관성이 없다.
법적 불가는 아니므로 **제외하지 않고 `W_SUBDIVIDED` 플래그**를 달아 웹에서 토글한다.

**역거리 하한은 두지 않는다** (Q-11). 역세권을 3순위로 둔 것이 설계 의도이고,
등급 임계값은 웹에서 사용자가 직접 조정한다. 하드 필터를 더 넣으면
tolerance 실험의 의미가 줄어든다.

## D-015 · 타일 정밀도는 용량보다 우선한다

**상태:** 확정 (2026-09-01)

타일 용량을 아끼려고 값을 정수로 절사했다가 **웹이 조용히 틀린 답을 낼 뻔했다.**

실 수는 `floor()`, 역세권은 등급 경계로 끊긴다. 입력이 조금만 어긋나면 결과가
한 칸씩 튀고, 그게 수익률로 증폭된다. 측정값:

| 양자화 | S₁ 최대오차 | 실수 불일치 | 등급 불일치 | 상위200 순서 |
|--------|------------|------------|------------|-------------|
| 공시지가 천원절사 + rf×1,000 | **6.6%p** | 490 | 108 | **114/200** |
| ×10 / rf×10,000 | 5.0e-03 | 19 | 10 | 200/200 |
| **×100 / rf×100,000** | **2.3e-07** | **0** | **0** | **200/200** |

파일 크기는 17.0MB → 20.1MB 로 3MB 늘었을 뿐이다 (상한 50MB).
**정확도를 3MB에 팔지 않는다.**

부수 발견: PNU 뒷 8자리(본번+부번)를 id로 쓰면 법정동이 다른 필지끼리
**15,322건 충돌**한다. 시군구 5자리만 떼고 뒤 14자리를 쓴다.

`scripts/07_verify_tiles.py` 가 이 전부를 매 빌드마다 검사한다.
타일을 다시 구운 뒤에는 반드시 실행한다.
